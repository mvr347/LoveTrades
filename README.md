# LoveTrades

Система поддерживаемых сервером торговель между игроками с защитой от обмана, налогами и боевыми ограничениями.

## Описание

LoveTrades предоставляет безопасный механизм обмена предметами и валютой между игроками:

- **Защищённые торговли** — обе стороны должны согласиться перед выполнением обмена
- **Система налогов** — сервер может взимать комиссию с торговель (процент или фиксированная сумма)
- **Боевые ограничения** — запрет на торговлю во время PvP боя (опционально)
- **Лимиты стеков** — ограничение количества одинаковых предметов за одну торговлю
- **Кулдауны** — минимум времени между торговлями одного и того же игрока с тем же партнёром
- **История торговель** — логирование для аудита и спора-разрешения
- **Интеграция LoveCore** — использование единой валюты для обмена

## Команды

| Команда | Алиасы | Описание | Пермишин |
|---|---|---|---|
| `/trade` | `lovetrades`, `торговля` | Инициировать торговлю | `axtrades.use` |
| `/lovetradesadmin` | `tradeadmin` | Административные команды | `axtrades.admin` |

### Подкоманды `/trade`

- `/trade <ник>` — отправить запрос на торговлю игроку
- `/trade accept` — принять входящий запрос на торговлю
- `/trade deny` — отклонить входящий запрос
- `/trade toggle` — включить/выключить получение торговых запросов
- `/trade cancel` — отменить активную торговлю

### Подкоманды `/lovetradesadmin`

- `/lovetradesadmin reload` — перезагрузить конфигурацию
- `/lovetradesadmin modifier <player>` — управлять налоговым модификатором для игрока
- `/lovetradesadmin history <player>` — показать историю торговель игрока

## Пермишины

| Пермишин | Описание | Default |
|---|---|---|
| `axtrades.use` | Разрешает команду `/trade` | true |
| `axtrades.bypass.tax` | Полный обход налогов и комиссий | false |
| `axtrades.bypass.combat` | Торговля в режиме PvP боя | false |
| `axtrades.bypass.cooldown` | Обход кулдауна между торговлями | false |
| `axtrades.bypass.stack-limit` | Обход лимита стеков | false |
| `axtrades.admin` | Административные команды | op |

## Конфигурация

### Основные параметры торговли

```yaml
trade:
  # Включить/выключить систему торговли
  enabled: true
  
  # Таймаут на принятие/отклонение запроса (в секундах)
  request-timeout-seconds: 60
  
  # Максимальная длительность торговли (пока оба игрока подтверждают)
  trade-session-timeout-seconds: 300
  
  # Требует ли торговля быть в одном мире
  same-world-required: true
  
  # Максимальное расстояние между игроками для торговли (в блоках)
  max-distance: 50
```

### Система налогов

```yaml
taxation:
  # Включить налоговую систему
  enabled: true
  
  # Тип налога: PERCENTAGE (процент) или FIXED (фиксированная сумма)
  type: PERCENTAGE
  
  # Размер налога (в процентах или абсолютное значение)
  amount: 5  # 5% от каждой торговли
  
  # Минимальный налог (чтобы очень дешёвые торговли не коснулись)
  min-tax: 10
  
  # Максимальный налог (капсинг дорогих торговель)
  max-tax: 1000
  
  # Кому идут налоги: SERVER, SELLER, BOTH
  tax-recipient: SERVER
  
  # Сообщение при взимании налога
  message: "&e%player% отдал &c%amount%&e монет налога"
```

### Боевые ограничения

```yaml
combat-restrictions:
  # Запретить торговлю во время боя
  enabled: true
  
  # Максимальное время после последнего урона чтобы считаться "в бою" (в секундах)
  combat-duration-seconds: 30
  
  # Сообщение об отказе при торговле в бою
  message: "&cВы находитесь в боевом режиме! Дождитесь окончания боя."
```

### Лимиты стеков

```yaml
stack-limits:
  # Максимально одинаковых предметов за одну торговлю
  max-stack-size: 64
  
  # Ограничение по типам предметов (например, алмазы максимум 32)
  item-specific:
    DIAMOND: 32
    EMERALD: 32
    NETHERITE_INGOT: 16
```

### Кулдауны

```yaml
cooldowns:
  # Кулдаун между торговлями с одним игроком (в минутах)
  same-player-cooldown-minutes: 5
  
  # Глобальный кулдаун между любыми торговлями (в секундах)
  global-cooldown-seconds: 0
  
  # Сообщение о кулдауне
  message: "&cПожалуйте, подождите %remaining% секунд перед следующей торговлей"
```

## Механика торговли

### Стандартный сценарий торговли

1. **Инициация** — игрок A использует `/trade <B>` для отправки запроса
2. **Ожидание** — игрок B получает сообщение с запросом на торговлю (60 сек таймаут)
3. **Принятие** — игрок B использует `/trade accept` 
4. **Сессия открывается** — оба игрока видят интерфейс торговли со слотами предметов
5. **Размещение предметов** — каждый игрок кладёт нужные предметы в свой слот
6. **Подтверждение** — обе стороны должны кликнуть кнопку "Готово"
7. **Обмен** — если оба согласны, обмен выполняется атомарно
8. **Налог** — если включен, налог взимается у получателя денег
9. **История** — торговля логируется для аудита

### Отмена торговли

Торговля может быть отменена если:
- Один из игроков использует `/trade cancel`
- Истечёт таймаут сессии (300 сек по умолчанию)
- Один из игроков отойдёт дальше `max-distance` (50 блоков)
- Один из игроков погибнет или выйдет из сервера

При отмене все предметы возвращаются в инвентарь.

### Налоговая система

- **Процент** — если `type: PERCENTAGE`, налог = (сумма × 5) / 100
- **Фиксированная сумма** — если `type: FIXED`, налог всегда = 5 монет
- **Капсинг** — налог никогда не меньше `min-tax` и не больше `max-tax`
- **Получатель** — налог может идти серверу (казну) или обратно продавцу

## Зависимости

### Мягкие зависимости

- **LuckPerms** — управление группами и пермишинами модификаторов налога
- **PlaceholderAPI** — интеграция плейсхолдеров
- **LoveCore** — система валюты для торговель монетами

## Интеграции

### LoveCore

Использует `LoveEconomy` для обмена физическими монетами. Все денежные части торговли проходят через LoveCore.

### PlaceholderAPI

| Плейсхолдер | Описание |
|---|---|
| `%lovetrades_trades_completed%` | Количество завершённых торговель |
| `%lovetrades_total_volume%` | Общая стоимость всех торговель |
| `%lovetrades_on_cooldown%` | Остаток кулдауна (в сек) |

## Структура данных

- `trades` — таблица завершённых торговель (дата, игрок A, игрок B, предметы, налог)
- `trade_items` — детали предметов в каждой торговле (тип, количество, NBT)
- `trade_cooldowns` — кулдауны между игроками (последняя торговля, окончание кулдауна)
- `tax_modifiers` — индивидуальные налоговые модификаторы для VIP игроков (например, -50% налога)

## Примечания

- Торговля атомарна — если произойдёт ошибка, всё откатывается и предметы возвращаются
- Предметы с NBT (чары, ники и т.д.) сохраняют свои данные при торговле
- История торговель используется в случае спора между игроками
- Администраторы с `axtrades.admin` могут посмотреть полную историю любого игрока
- Налоги накапливаются на счёте сервера для использования в экономике
